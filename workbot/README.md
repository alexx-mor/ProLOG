# WorkBot

WorkBot — бот для российского мессенджера MAX, который собирает ежедневные
отчёты сотрудников из рабочих групп, сохраняет исходные сообщения и формирует
Excel-книгу с отдельным листом для каждого сотрудника.

Сейчас WorkBot является самостоятельным модулем внутри репозитория ProLOG.
Бот и ProLOG используют разные SQLite-базы:

- WorkBot: `data/workbot.sqlite3`;
- ProLOG: `data/prolog.sqlite3`.

Прямая запись отчётов в ProLOG пока не реализована. План интеграции описан в
[docs/PROLOG_INTEGRATION.md](docs/PROLOG_INTEGRATION.md).

## Текущие возможности

- Получение новых и изменённых сообщений через Long Polling MAX.
- Работа в разрешённых группах MAX.
- Сохранение исходного текста, автора, времени и идентификатора сообщения.
- Защита от повторной обработки одного сообщения.
- Разбор строгого шаблона отчёта.
- Эвристический разбор свободной формы и старой истории сообщений.
- Поддержка нескольких сотрудников и дат в одном историческом сообщении.
- Подтверждение номера, привязанного к MAX-аккаунту, через `/register`.
- Автоматическая привязка MAX ID к сотруднику ProLOG по уникальному подтвержденному телефону.
- Ручная привязка как резерв для неоднозначных случаев.
- Формирование Excel по всем данным или за выбранный период.
- Отдельный лист Excel для каждой фамилии сотрудника.
- Поиск неполных сообщений и отсутствующих отчётов.
- Кнопочное меню в личном диалоге владельца.
- Ограничение управляющих команд по MAX ID владельца.
- Загрузка истории конкретной группы.

## Что пока не реализовано

- Получение объектов, местонахождений и видов работ из справочников ProLOG.
- Автоматическое еженедельное напоминание в группе.
- Серверный Webhook и работа как постоянная служба.

## Требования

- Python 3.12 или совместимая версия.
- Пакет `openpyxl`.
- Созданный бот MAX.
- Права администратора у бота в группе, сообщения которой он должен получать.

Установка зависимостей проекта:

```powershell
python -m pip install -r requirements.txt
```

## Настройка

1. Скопировать `workbot.env.example` в `private/workbot.env`.
2. Заполнить `WORKBOT_TOKEN`.
3. Заполнить `WORKBOT_OWNER_IDS`.
4. При необходимости ограничить список групп через
   `WORKBOT_ALLOWED_CHAT_IDS`.
5. Не добавлять `private/workbot.env` в Git.

Пример без секретных значений:

```dotenv
WORKBOT_TOKEN=
WORKBOT_OWNER_IDS=
WORKBOT_ALLOWED_CHAT_IDS=
WORKBOT_DENY_UNAUTHORIZED=false
WORKBOT_DATABASE=data/workbot.sqlite3
WORKBOT_EXPORT_DIR=exports
WORKBOT_POLL_TIMEOUT=30
```

Текущий тестовый токен хранится только в `private/workbot.env`. Перед рабочей
эксплуатацией его необходимо отозвать и выпустить новый.

## Запуск и служебные команды

Проверить соединение с MAX:

```powershell
python -m workbot check
```

Узнать MAX ID отправителя:

```powershell
python -m workbot identify
```

Запустить Long Polling:

```powershell
python -m workbot run
```

Импортировать старую историю группы:

```powershell
python -m workbot backfill CHAT_ID
```

Создать Excel локально:

```powershell
python -m workbot export
```

## Формат отчёта

Строгий формат:

```text
Дата: 30.07.2026
Виды работ: Монтаж и проверка шкафа автоматики
Затраченное время: 7,5
Объект: Жигалово
Местонахождение: Производство
```

Свободная форма также разбирается, но считается менее надёжной. Исходный текст
всегда сохраняется, поэтому после улучшения правил его можно обработать
повторно.

## Команды владельца

| Команда | Назначение |
|---|---|
| `/start`, `/menu` | Открыть кнопочное меню |
| `/register`, `/phone` | Подтвердить телефон для привязки к сотруднику ProLOG |
| `/help` | Показать справку |
| `/template` | Получить шаблон отчёта |
| `/id` | Показать MAX ID владельца |
| `/users` | Показать найденных пользователей и привязки |
| `/bind MAX_ID \| ФИО` | Привязать MAX ID к сотруднику |
| `/chats` | Показать обнаруженные группы |
| `/stats` | Показать статистику |
| `/errors` | Показать последние ошибки разбора |
| `/excel [ДД.ММ.ГГГГ] [ДД.ММ.ГГГГ]` | Получить Excel |
| `/missing [ДД.ММ.ГГГГ] [ДД.ММ.ГГГГ]` | Найти пропуски по рабочим дням |

Кнопочное меню дублирует наиболее частые команды: Excel, статистика,
сотрудники, группы, ошибки, отсутствующие отчёты и шаблон.

## Доступ

- Управляющие команды и callback-кнопки выполняются только для MAX ID из
  `WORKBOT_OWNER_IDS`.
- Любой пользователь может выполнить `/register` в личном диалоге; остальные
  управляющие команды доступны только владельцам.
- Обычные сообщения в группах не получают ответа: бот собирает отчёты молча.
- Если заполнен `WORKBOT_ALLOWED_CHAT_IDS`, данные из остальных групп не
  сохраняются.

## Данные и резервное копирование

WorkBot хранит:

- пользователей MAX, подтвержденные телефоны и ручные привязки ФИО;
- обнаруженные группы;
- исходные сообщения;
- статус и ошибку разбора;
- структурированные отчёты;
- позицию Long Polling.

Перед повторной обработкой истории или изменением правил парсинга следует
создать копию `data/workbot.sqlite3`. Excel-файлы создаются в `exports/`.
