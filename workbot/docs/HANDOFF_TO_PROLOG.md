# Передача WorkBot в контекст разработки ProLOG

## Сообщение для разработчика или соседнего чата

В этом репозитории появился отдельный модуль `workbot/` для мессенджера MAX.
Он собирает ежедневные отчёты из рабочих групп, сохраняет исходные сообщения,
разбирает строгий и свободный формат, импортирует старую историю и формирует
Excel. Управлять ботом может только владелец; в группах отчёты собираются
молча.

WorkBot использует отдельную базу `data/workbot.sqlite3`. Контролируемый импорт
в журнал ProLOG уже реализован. Сотрудники, объекты, изделия и алиасы хранятся
в отдельных компонентных базах и связываются с журналом устойчивыми ID.

Перед изменением кода необходимо прочитать:

1. `workbot/README.md`;
2. `workbot/docs/PRINCIPLES.md`;
3. `workbot/docs/PROLOG_INTEGRATION.md`;
4. `workbot/CHANGELOG.md`.

Главная задача следующего этапа — сделать контролируемый, идемпотентный импорт
распознанных отчётов в `WorkLogEntries` ProLOG.

## Первый рекомендуемый пакет работ

1. Исправить поддержку дробных часов в ProLOG:
   `WorkLogEntry.hours: float` и чтение без преобразования к `int`.
2. Добавить в ProLOG миграции таблиц:
   `MaxUserBindings`, `EmployeeAliases`, `ObjectAliases` и
   `WorkBotImportRows`.
3. Реализовать read-only/dry-run импорт из `data/workbot.sqlite3`.
4. Сопоставлять сотрудников только с `Employees.id`, объекты — только с
   `Objects.id`.
5. Не создавать объект автоматически по тексту сообщения.
6. Все неоднозначные строки помещать в очередь проверки.
7. Гарантировать уникальность импорта по
   `(max_message_id, source_index)`.
8. Покрыть миграции и повторный импорт тестами.

После этого следует добавить экран ProLOG «Входящие отчёты», где оператор
сможет подтвердить сотрудника, объект, местонахождение, часы и сохранить
обнаруженный алиас. Пример: подтверждённый алиас
`жимолово → Objects.id объекта «Жигалово»`.

## Важные ограничения

- Не переносить токен MAX в исходный код или документацию.
- Текущий тестовый токен перед эксплуатацией должен быть заменён.
- Не импортировать спорные результаты парсера напрямую в табель.
- Не связывать сущности только по отображаемому ФИО или названию: после
  подтверждения использовать числовые ID ProLOG.
- Не терять исходный текст и ссылку на сообщение MAX.
- Редактирование уже импортированного сообщения должно попадать на повторное
  подтверждение, а не молча менять табель.

## Точки входа в код

- События и команды: `workbot/service.py`.
- База WorkBot: `workbot/storage.py`.
- Парсеры: `workbot/parser.py`, `workbot/legacy_parser.py`.
- Импорт истории: `workbot/backfill.py`.
- Модели и база ProLOG: `models.py`, `database.py`.
- Бизнес-слой ProLOG: `services.py`.

Полный рекомендуемый план, SQL-эскизы, алгоритмы сопоставления и критерии
готовности находятся в `workbot/docs/PROLOG_INTEGRATION.md`.
