# История изменений WorkBot

Все заметные изменения WorkBot фиксируются в этом файле. Проект находится на
этапе пилотной эксплуатации.

## 2026-08-03 — Ручная привязка MAX ID

### Изменено

- Команды `/register` и `/phone` отключены: телефон больше не используется для
  автоматической идентификации сотрудника.
- Подтверждение связи выполняет администратор в ProLOG по схеме
  `MAX ID → Employees.id`.
- Старые поля телефонов в SQLite сохранены для совместимости и не влияют на
  сопоставление новых отчетов.

### Проверено

- Повторная синхронизация немедленно применяет новую привязку к уже загруженным
  входящим отчетам и не создает дубликаты.

## 2026-08-03 — Подтвержденная идентификация сотрудников

### Добавлено

- Саморегистрация сотрудника командами `/register` и `/phone`.
- Штатная кнопка MAX для передачи номера, привязанного к аккаунту отправителя.
- Проверка HMAC-подписи контакта токеном бота.
- Хранение подтвержденного телефона и времени подтверждения в таблице `users`.
- Миграция существующей базы без пересоздания и потери отчетов.

### Безопасность

- Пересланные контакты и номера без корректной подписи не принимаются.
- Один подтвержденный номер нельзя закрепить за двумя MAX ID.
- Никнейм и отображаемое имя MAX не используются как доказательство личности.

### Проверено

- Успешно пройдены 22 теста WorkBot и интеграции с ProLOG.

## 2026-07-30 — Кнопочное управление

### Добавлено

- Inline-клавиатура MAX для владельца.
- Кнопки получения Excel, статистики, списка сотрудников, списка групп,
  ошибок, отсутствующих отчётов и шаблона.
- Команды `/start` и `/menu`.
- Обработка события `message_callback`.
- Проверка прав владельца для каждого callback-события.

### Проверено

- Успешно пройдено 14 автоматических тестов.
- Бот перезапущен с новой версией и меню отправлено владельцу.

## 2026-07-30 — Импорт истории и разбор свободной формы

### Добавлено

- Постраничная загрузка старых сообщений выбранной группы MAX.
- Хранение исторических отчётов отдельно от отчётов строгого формата.
- Эвристический разбор сообщений со свободной структурой.
- Поддержка нескольких дат и нескольких сотрудников в одном сообщении.
- Извлечение временных интервалов, объекта, местонахождения и описания работ.
- Коэффициент уверенности и исходный фрагмент для исторических записей.
- Повторная обработка ранее сохранённых сообщений.

### Выполнено в тестовой базе

- Обнаружена и импортирована рабочая группа с ежедневными отчётами.
- Загружено 1121 текстовое сообщение.
- Сформировано 1755 строк отчётов за период с 12.01.2026 по 30.07.2026.
- Создана Excel-книга с 27 листами сотрудников.

### Ограничения

- Часть старых сообщений не содержит времени; оно оставлено нулевым, а не
  придумано автоматически.
- Выделенные объект и местонахождение ещё не сверяются со справочниками ProLOG.
- Эвристический результат требует механизма проверки перед записью в ProLOG.

## 2026-07-30 — Первый рабочий прототип

### Добавлено

- Клиент MAX API без внешнего HTTP-фреймворка.
- Long Polling для событий `message_created` и `message_edited`.
- SQLite-хранилище `data/workbot.sqlite3`.
- Защита от повторного сохранения по идентификатору сообщения MAX.
- Строгий парсер пяти полей отчёта.
- Обновление данных после редактирования сообщения.
- Excel-экспорт с отдельным листом по фамилии сотрудника.
- Команды владельца `/users`, `/chats`, `/bind`, `/stats`, `/errors`,
  `/excel`, `/missing`, `/template` и `/id`.
- Загрузка файлов в MAX и отправка сформированного Excel владельцу.
- Настройки через закрытый файл `private/workbot.env`.
- Автоматические тесты парсера, хранилища, Excel и контроля доступа.

### Безопасность

- Управление разрешено только перечисленным MAX ID владельца.
- Посторонние личные сообщения игнорируются либо получают отказ согласно
  настройке.
- Токен не хранится в документации и не должен попадать в Git.
