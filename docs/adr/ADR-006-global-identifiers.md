# ADR-006: Global identifiers / future API identity

Статус: принято 09.08.2026

## Контекст

Локальные SQLite-таблицы используют `INTEGER PRIMARY KEY`. Для будущей
серверной версии и API RAMOR Software локальные ID недостаточны: одинаковые
числа могут существовать в разных установках, а перенос/слияние баз создаст
конфликты.

## Решение

- Существующие `id INTEGER` сохраняются и остаются внутренними локальными
  ключами и целями текущих внешних ссылок.
- Для сущностей, выходящих через будущий API, предусматривается отдельный
  `uid UUID` — глобальный, неизменяемый и уникальный идентификатор.
- В SQLite UUID хранится в канонической строковой форме в поле `uid TEXT` с
  уникальным индексом; API представляет его как UUID.
- Для совместимости Python 3.12 базовым форматом генерации выбран UUID v4.
- API не должен использовать локальный `id` как глобальную идентичность.
- `Employee` и `Actor` получают разные UID. Возможная связь между ними хранится
  отдельно и не делает сущности тождественными.
- Новые production-сущности смогут получать UID с момента создания.

## Решение для этапа 0

UUID не добавляются в существующие пользовательские таблицы сейчас. Причины:

- заполнение UID изменит каждую существующую пользовательскую строку;
- production/API еще не используют эти значения;
- сначала нужен проверенный версионированный мигратор и политика экспорта;
- требование этапа 0 запрещает изменение пользовательских данных.

## Будущая аддитивная миграция

1. Добавить nullable-столбец `uid TEXT` только в выбранные API-сущности.
2. В одной контролируемой миграции заполнить UUID v4 существующим строкам.
3. Проверить уникальность и формат, создать уникальный частичный индекс.
4. Перевести сервисы создания на обязательную генерацию UID.
5. После периода совместимости обеспечить `NOT NULL` на уровне схемы либо
   эквивалентным проверяемым ограничением.
6. Добавить таблицу сопоставления при импорте из другой установки, не меняя
   уже выданные UID.

## Следствия

- Локальная производительность и существующие связи по INTEGER сохраняются.
- Базы можно будет объединять и синхронизировать без перенумерации сущностей.
- UID является идентичностью, но не содержит бизнес-смысла и не переиспользуется.
