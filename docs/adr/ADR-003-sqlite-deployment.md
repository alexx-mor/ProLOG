# ADR-003: SQLite deployment

Статус: принято 09.08.2026

## Контекст

ProLOG использует основную SQLite-базу и компонентные файлы сотрудников,
объектов, изделий и алиасов. Межфайловые внешние ключи SQLite не поддерживает.
Рабочие файлы могут быть размещены на локальном сервере.

## Решение

- На текущем этапе сохраняется SQLite и существующее разбиение файлов.
- Отдельный файл `production.sqlite3` не создается.
- Новые production-таблицы в будущем размещаются в `prolog.sqlite3`, чтобы
  транзакционно связываться с журналом работ.
- Каждый файл имеет собственную таблицу `SchemaMigrations` и диагностируемую
  версию схемы.
- Межфайловые ссылки проверяются приложением при запуске.
- До появления серверного API эксплуатационная модель предполагает одного
  активного писателя.

## Критерии перехода к серверной СУБД/API

- несколько клиентов одновременно изменяют общие данные;
- WorkBot и настольные клиенты должны писать независимо;
- сетевые блокировки становятся эксплуатационной проблемой;
- необходимы централизованные права, аудит и резервное копирование;
- объем вложений требует отдельного серверного хранилища.

## Следствия

- Модульная граница определяется кодом и сервисными контрактами, а не новым
  файлом SQLite.
- Репозитории должны позволить заменить хранение без изменения доменной модели.
