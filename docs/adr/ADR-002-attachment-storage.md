# ADR-002: Attachment storage

Статус: принято 09.08.2026

## Контекст

Будущая история производства будет включать фотографии. Хранение больших
бинарных данных внутри SQLite увеличивает размер рабочей базы, длительность
транзакций, вероятность блокировок и стоимость резервного копирования.

## Решение

- Файлы вложений хранятся вне SQLite в управляемом каталоге.
- SQLite хранит только метаданные, относительный `storage_key`, SHA-256,
  MIME-тип, размер, исходные идентификаторы и даты.
- Абсолютные пути конкретного компьютера не сохраняются как доменные данные.
- Запись файла выполняется атомарно: временный файл, проверка хэша, затем
  переименование.
- Резервная копия считается полной только при согласованном копировании БД и
  каталога вложений.
- Потерянные и осиротевшие файлы выявляются штатной диагностикой.

## Следствия

- Каталог может быть локальным на MVP и серверным позднее.
- Дедупликация физического содержимого возможна по SHA-256, но происхождение
  каждого логического вложения сохраняется отдельно.
- Реализация фотографий не входит в этап архитектурной стабилизации.
